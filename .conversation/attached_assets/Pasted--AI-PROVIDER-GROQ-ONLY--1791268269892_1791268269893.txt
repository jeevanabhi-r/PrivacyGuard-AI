========================================================
AI PROVIDER — GROQ ONLY
========================================================

IMPORTANT:

Use GROQ as the ONLY LLM provider for this project.

DO NOT use:
- Google Gemini
- Gemini API
- Google AI Studio
- OpenAI
- Anthropic
- OpenRouter

The AI Privacy Assistant must use the Groq API.

Use the official Groq SDK or compatible Groq API implementation.

Store the Groq API key ONLY as a Supabase Edge Function secret.

Environment variable:

GROQ_API_KEY=

NEVER expose GROQ_API_KEY to React/frontend code.

NEVER put GROQ_API_KEY inside:
- .env variables prefixed with VITE_
- React components
- browser JavaScript
- public files
- GitHub
- client-side source code

========================================================
GROQ ARCHITECTURE
========================================================

Frontend
   ↓
Supabase Edge Function
   ↓
Groq API
   ↓
LLM Response
   ↓
Supabase Edge Function
   ↓
Frontend

The browser must NEVER call Groq directly.

Create:

supabase/functions/privacy-assistant/

The Edge Function should:

1. Authenticate the Supabase user
2. Validate the request
3. Apply reasonable input limits
4. Send the request to Groq
5. Receive the LLM response
6. Return the response to the frontend
7. Save conversation history to Supabase

========================================================
GROQ MODEL CONFIGURATION
========================================================

Make the model configurable through an environment variable:

GROQ_MODEL=

Do NOT hardcode the model throughout the application.

Use a suitable currently available Groq chat model.

If GROQ_MODEL is not provided, define one default model in the Edge Function configuration.

Keep the AI service modular so the model can be changed later without changing the frontend.

========================================================
AI SYSTEM PROMPT
========================================================

Use this system instruction for PrivacyGuard AI:

"You are PrivacyGuard AI, a cybersecurity and digital privacy education assistant.

Your purpose is to teach users how to improve their digital privacy safely.

You may explain:
- privacy settings
- app permissions
- location privacy
- browser privacy
- social media privacy
- tracking
- cookies
- third-party data sharing
- authentication safety
- phishing awareness
- personal data protection

Always provide defensive and educational guidance.

IMPORTANT SAFETY RULES:

Never ask the user for:
- passwords
- OTPs
- API keys
- authentication cookies
- private keys
- recovery codes
- banking credentials
- session tokens

Never request sensitive credentials.

Never claim that you can directly modify the user's Google, Instagram, Facebook, WhatsApp, Microsoft, Apple, or other third-party account settings.

Instead, explain the safe steps the user can perform themselves.

Keep explanations understandable for normal users.

When appropriate:
1. Explain the privacy risk
2. Explain why it matters
3. Give step-by-step actions
4. Give a practical recommendation

If the question is unrelated to privacy or cybersecurity education, politely redirect the user toward the purpose of PrivacyGuard AI."

AI RESPONSE STRUCTURE
========================================================

Ask Groq to return useful structured answers.

Prefer responses containing:

- Short explanation
- Risk
- Why it matters
- Recommended actions
- Step-by-step guide
- Safety note when appropriate

Render markdown safely in the frontend.

Do not render arbitrary HTML from the AI response.

========================================================
AI RATE LIMIT / ERROR HANDLING
========================================================

Because Groq has API rate limits, implement graceful handling.

If Groq returns:

429 / rate limit

show:

"PrivacyGuard AI is temporarily busy. Please try again in a moment."

Do NOT crash the application.

Also handle:

401
403
500
502
503
timeout
network failure

with user-friendly messages.

Add a retry button.

Do not automatically retry continuously.

Use reasonable request limits.

========================================================
AI INPUT PROTECTION
========================================================

Limit message length.

Example:

Maximum user message:
4000 characters.

Limit conversation history sent to Groq.

Do not send unlimited historical messages.

Use only the necessary conversation context.

This reduces token usage and helps with rate limits.

========================================================
AI FALLBACK
========================================================

If GROQ_API_KEY is missing or Groq is temporarily unavailable:

DO NOT break the application.

Show:

"AI Assistant is currently unavailable."

Provide a fallback privacy knowledge response system using the application's built-in privacy guides.

The user should still be able to:

- Browse privacy guides
- Complete checklists
- Learn lessons
- Take quizzes
- View recommendations
